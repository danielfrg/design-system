# design-system

Shared design system.

- Many apps share the design based on this design system.
- The files in `public/` are design to be copy pasted into other apps.
- To keep apps in sync run `pnpm sync` (see Syncing apps below), don't copy files by hand.

## Syncing apps

- `sync.toml` lists each app that uses these files: its repo `path` (relative to this repo), the
  `dest` folder inside it, the `theme` (a folder in `public/v1`) and the `custom` components (folders
  in `public/v1/custom`) it uses.
- `pnpm sync` copies them: the theme to `<dest>/theme/{tokens,components}.css` and each component to
  `<dest>/custom/<name>/`. `pnpm sync <app>` limits it to one app.
- `pnpm sync --check` changes nothing and exits 1 if an app has drifted (a file differs, is missing, or
  is unexpected). Run it after editing anything in `public/v1`.
- The `dest` folder is owned by the sync: it is deleted/overwritten to match. Apps never edit it; changes
  are made here and synced. App-specific styles live outside `dest`.
- Adding an app, or a theme/component to one, is an edit to `sync.toml`, then `pnpm sync`.
- Syncing writes into other repos' working trees: don't commit there unless asked.

## ui-sdk

- Before using ui-sdk, follow the ui-sdk skill (`.agents/skills/ui-sdk`) and read
  `node_modules/@ui-sdk/svelte/docs/llms.txt`.
- To build a new component, also search `node_modules/@ui-sdk/svelte/docs/core.md` by heading,
  and read `rendering.md` next to it.
- The gallery's component pages render the ui-sdk docs examples vendored in
  `src/gallery/vendor/ui-sdk-examples` (see its README to update them). Don't edit those files.
- `public/v1/<theme>/{tokens,components}.css` are the design system for ui-sdk apps, one folder
  per theme. They are generated by `scripts/build-design-css.mjs` (runs in `pnpm build`): the
  ui-sdk theme from the vendored docs styles, other themes from `themes/<theme>/tokens.css` and
  an optional `overrides.css`. Edit those sources, not the generated files.
